# 与 AI 协作实现 Agent Hub：分享准备

当前共 24 页。顺序为：需求 → 角色 → Workflow → 与 AI 沟通并实现 → 迭代验证 → 协作复盘。

## 逐页目录

1. 封面
2. 从想法到实现：这次分享沿着什么顺序展开？
3. 先拆需求，再确定主 Agent、功能 Agent 和业务 Agent
4. 职责怎样划分：Hub 管整体，功能 Agent 各自交付
5. Workflow：先画主线，再补关键判断
6. 片段 1：先判断用户到底想做什么
7. 片段 2：决定怎么找到合适的 Agent
8. 片段 3：把复杂任务拆成可以交接的步骤
9. 把前面的设计写进 README，让 AI 有据可依
10. README 也记录“为什么这样做”和“还有什么没定”
11. 告诉 AI：每类内容具体存在哪里
12. “我的格式放在哪里？”——先给 AI 一份可引用的规范
13. 一个 Agent 文件，最外层固定三部分
14. Instruction：从“你是谁”写到“你该怎么做”
15. 真实例子：让差异比较结果能交给下一个 Agent
16. 文件写好了，还要让其他 Agent 找得到它
17. 流程怎么补漏：用一个追问发现缺失的分支
18. 怎么检查流程：用用户提问走一遍规则
19. 修改需求时，告诉 AI 同步改哪些地方
20. 把笼统的修改要求变成可以验收的任务
21. 最后一步：把待验证事项写下来，交给下一轮
22. 我们和 AI 怎样分工：决定、展开、审核与沉淀
23. 用一段真实对话串起：需求、设计、修改与结果
24. 结尾

## 讲述衔接

- 第 2 页提出业务想法和整场路线。
- 第 3–4 页从需求拆出角色；接着第 5–8 页展示角色如何在流程中配合。
- 第 9 页转入实现：“设计讨论清楚以后，如何让 AI 按同一套约定写文件？”随后介绍 README、文件结构、格式、指令与 Registry。
- 第 17–18 页用补漏和用户提问说明如何发现问题；第 19–21 页说明如何具体反馈、同步修改并保存验证任务。
- 第 22 页复盘人与 AI 的分工；第 23 页以真实对话和修改结果串起全过程；第 24 页结尾。
