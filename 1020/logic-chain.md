# 当前讲述逻辑

**想法 → 与 AI 拆角色 → 初步主线 → 从用户角度追问补分支 → summarize 到 README → 查看真实文档 → 按规范生成定义 → 根据 TODO 分步推进 → 检查生成结果 → 新想法出现 → 分析与既有规则的冲突 → 明确候选边界 → 接受后同步文件并回归检查 → 验证运行与结果 → 复用沟通模板。**

## 新想法的贯穿例子

用户可能觉得简单任务的反复确认太繁琐。先请 AI 分析，不立刻修改源文件。

1. 阅读当前 README、流程图和相关指令。
2. 找到新想法与当前执行确认规则的冲突。
3. 区分任务简单、输入齐全、已有授权、权限与外部动作。
4. 比较总结已提供文本与把总结发给团队，形成候选边界。
5. 接受后更新 Decision Log、规则、流程图、Hub/Executor 指令和测试。
6. 检查新路径，也检查旧有确认与权限边界，记录到 TODO。

这一段是新提案，不表示原项目已经修改或验证通过。生成项目文件的实施节奏，与 Agent Hub 执行业务任务的授权是两回事。
