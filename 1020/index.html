# English Name

英文名称：English Name
中文名称：中文名称

## Description
核心能力、适用场景、主要输出或边界。

## Instruction
职责、输入、执行规则、输出与限制。

把要求写成可检查的条件

Description：简洁英文段落，最多 800 字符。

整个 TXT：少于 8000 字符。

业务 Agent：包含中英文名称。

使用 UTF-8 纯文本，便于手动配置时复制。

以上是本项目的格式约定；具体说明和代码块仍可保留在 TXT 文本中。

04 · IMPLEMENT WITH AI

Instruction：从“你是谁”写到“你该怎么做”

触发与输入

什么时候使用？必须提供什么材料？缺少输入时返回 needs_clarification，列出最少必需字段。

执行与边界

按什么步骤处理？依据哪些材料？哪些动作超出职责？结果交给谁？

输出与失败

需要返回哪些结果字段？如何表示完成、澄清和失败？怎样保留来源及未解决事项？

04 · IMPLEMENT WITH AI

文件写好了，还要让其他 Agent 找得到它

定义文件：能力怎么执行

各 Agent 的 TXT 保存职责、输入要求、处理规则和返回格式。

Registry：能力怎么发现

Agent-Registry.txt 保存名称、分类、标签、描述、能力、限制、权限和状态。

可以这样和 AI 说 · 示例

新增业务 Agent 后，请同步 Agent-Registry.txt。核对名称、描述、分类、标签、权限和状态与定义一致，并检查目录计数及引用。不要只生成一个孤立的 TXT 文件。

本项目以 Registry 作为分类、计数和推荐元数据的统一来源。Active 表示定义可发现，运行可用性需要另行验证。

怎么检查流程：用用户提问走一遍规则

拿什么问题检查沿流程核对什么发现偏差后怎么反馈
“你有哪些 Agent？”是否只返回概览，未进入业务执行？补充浏览与执行的意图区分

我们和 AI 怎样分工：决定、展开、审核与沉淀

我来确定与审核

确定要解决的问题、目标用户和预期结果。

决定角色分工、关键边界，以及哪些方案接受或调整。

审核流程是否符合业务意图，核对真实结果。

让 AI 帮忙展开与实现

枚举可能的用户问法，提出遗漏分支和澄清问题。

按约定整理流程、编写指令、同步定义与索引。

检查规则冲突与文件一致性，报告未完成事项。

提出目标说清想完成什么
→
AI 展开方案流程、分支与文件
→
审核并反馈指出具体偏差
→
写回项目规范、指令与待办
