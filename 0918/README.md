# From Chatting with AI to Working with AI

`index.html` 当前实际包含 18 页演示内容。本文记录将其拆为三次分享的建议，尚未据此调整演示稿。

## 三次分享的整体安排

主线：**把任务说清楚 → 把结果做可靠 → 把方法变成流程。**

建议在第 7 页和第 11 页之后分段，按完整主题划分，不平均分配页数。

| 次数 | 主题 | 当前对应页码 | 核心问题 |
| --- | --- | --- | --- |
| 第一次 | 从随口提问到清晰的工作任务 | 第 1–7 页 | 怎样让 AI 理解当前到底要做什么？ |
| 第二次 | 从 AI 回答到可交付的工作成果 | 第 8–11 页 | 怎样判断结果好用、可信、可以交付？ |
| 第三次 | 从一次成功到可复用的 Workflow 与 Agent | 第 12–18 页 | 怎样让这套方法下次继续用，并应对变化？ |

## 第一次：把任务说清楚

从第 2 页“让 AI 检查文件，但要求过于宽泛”的例子切入，讲为什么需要先对齐目标、输入、规则和输出；再解释 AI 使用的不只是最后一句话，还有整个上下文，因此对话越长，越需要处理旧版本、冲突要求和无关信息。

最后用第 7 页的 Continuation Brief 收尾，让听众带走一个整理上下文、继续工作的具体方法。

**逻辑链：模糊提问 → 执行前对齐 → 理解上下文 → 识别污染 → 整理成清晰任务简报。**

建议带走的成果：一份明确当前目标、有效输入、确认规则、未知问题和下一步的任务简报。

## 第二次：把结果做可靠

从“分析有了，但一大段文字不方便领导使用”切入，先讲输出要匹配读者、用途、格式和篇幅，再讲如何定向修改输出，以及如何区分事实、推断和未知。

最后落到输入、计算、证据和人工判断四层检查，用“从 1 增加到 3，增长 200%”说明数字正确也可能表达失真。

**逻辑链：定义交付标准 → 整理输出 → 检查结论来源 → 验证数字和表达 → 人工审核交付。**

这部分虽然只有四页，但信息密度高，适合增加一个修改前后的对照练习。

建议带走的成果：一份经过审核的交付物，以及输出标准和验证清单。

## 第三次：把方法变成可复用流程

从第 12 页“这周经过多轮修改终于完成，下周还要重新来吗？”切入，提取稳定步骤，定义每步的输入、动作、输出、检查和异常处理，再明确 AI、工具和人的分工。

之后引出：当下一步需要根据中间结果选择时，如何从固定 Workflow 走向 Agent，并设置权限、停止条件和人工检查点。

**逻辑链：复盘成功过程 → 提取固定步骤 → 加检查关口 → 明确分工并保存文件 → 判断是否需要动态决策 → 设计有边界的 Agent。**

第 18 页的 RAG、Memory、Multi-Agent 等内容建议作为展望简短带过，避免扩展成多个新主题。

建议带走的成果：一份可复用流程，以及判断使用 Workflow 还是 Agent 的依据。

## 给带教审查的说明

我计划把这套分享拆成三次，沿着“任务定义—结果验证—流程复用”展开。第一次讲如何明确需求和管理上下文，让 AI 理解任务；第二次讲如何规范输出、核查证据和数字，把回答变成可交付成果；第三次讲如何将成功经验沉淀为 Workflow，并进一步判断何时需要有边界的 Agent。三次用同一个案例递进，每次都有一个可以直接带走的方法或模板。
