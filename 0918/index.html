Define the output contract before generating
For this case, the audience is PM and leadership, the purpose is to prepare the Project Review, the format should be a Snapshot plus Risk Table and Decisions Needed, and the length should stay within one page. The contract is conclusions first, calculation detail in the appendix, every finding supported by source evidence, and every high-risk item tied to an owner, next step, or decision.
The output may not be obviously wrong, but if the reader still has to search through a long paragraph to find the point, it is not yet a good work deliverable.
Same analysis, different people need different output. Output has no single correct form. The same analysis should present different levels of detail for analysts, project managers, and leadership.

Output and Reliability

Five Common Output Problems
Too long
Use three conclusions, max two sentences each.
Too complex
Write for a non-technical manager.
Wrong format
Use a Finding / Evidence / Action table.
No priority
Sort High / Medium / Low and show the top three.
No action
Add Owner, Next Step, or Decision Needed.
Do not rerun the analysis or change verified numbers. Only reorganize the current output:
  1. Start with the three most important conclusions.
  2. Keep each conclusion under two sentences.
  3. Use a Finding / Evidence / Action table.
  4. Move technical details to the Appendix.
  5. Mark uncertain content separately.
  6. Do not add information that is not in the original data.
Output Repair Prompt
Reorganize the verified analysis into a meeting-ready deliverable. Keep the numbers unchanged, lead with the most important findings, separate evidence from interpretation, move supporting detail to the appendix, and clearly mark anything uncertain or unsupported by the source data.
