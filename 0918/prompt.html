Problem. The review scope is too broad.“Any issues” does not define the required checks, including denominator, population filter, counts, percentages, sorting, and consistency.
Problem. The output format is unclear.“Tell me” does not define a usable review structure with findings, evidence, corrected values, severity, and next steps.
Problem. The finding is not confirmed.“Appears” does not confirm whether Placebo N=6 is wrong, what the correct value is, or which source supports it.
Problem. The impact is not quantified.“Some” does not identify the affected rows or show their current and corrected values.
Problem. The action is not specific.“Review with the programmer” does not specify what needs to be fixed, rerun, and reconciled.

Structure Before PromptingUse when the task is still unclear. Ask AI to help identify missing information and turn rough ideas into a structured prompt.

Align Before ExecutingUse when the prompt is mostly defined. Ask AI to confirm its understanding and execution plan before starting.
USER

  2. which files you plan to use;

Audience: Statistical programmer responsible for QC resolution.

Purpose: Resolve QC findings quickly and reproducibly.

Priority: Location → discrepancy → impact → action.

Format: Structured issue list with exact source references.

Length: ≤5 lines per issue.

Exclusions: Do not infer root cause without table, dataset, variable, or log evidence.

Audience: Statistician responsible for interpretation and consistency.

Purpose: Confirm whether findings affect analysis conclusions.

Priority: Definition → population → estimate → uncertainty.

Format: Short review memo with assumptions and open questions.

Length: One concise paragraph per analysis point.

Exclusions: Do not change statistical interpretation without confirmation.

Audience: Project lead responsible for decisions and risk priority.

Purpose: Understand current project risk and required decisions.

Priority: Risk → business impact → owner → next step.

Format: Snapshot plus decision-needed bullets.

Length: Three key points, each under two sentences.

Exclusions: Do not include technical calculation detail in the main summary.

Output Repair Prompt
USERReorganize the verified analysis into a meeting-ready deliverable. Keep the numbers unchanged, lead with the most important findings, separate evidence from interpretation, move supporting detail to the appendix, and clearly mark anything uncertain or unsupported by the source data.

AIThe Placebo percentage is incorrect because the table program used the wrong population filter.
ObservedTable: 12/40 (30.0%)
EvidenceAnalysis dataset: 12/38 (31.6%)
Supported FindingThe denominator is inconsistent.
↓
⚠️ Unsupported ExplanationThe program used the wrong population filter.
Because we do know the denominator is inconsistent, but from the table and dataset alone, we do not know why. It may be the population filter, input dataset, macro parameter, derivation, or version issue.
FACTDirectly supportedThe table uses N=40, while the specified analysis population in the analysis dataset contains N=38.
INFERENCEReasonable, but needs verificationThe discrepancy may come from the population selection logic.

Evidence Check Prompt
USERReview each key claim and classify it as FACT, INFERENCE, or UNKNOWN based only on the available evidence. Treat a claim as FACT only when it is directly supported by the source data and cite that source; label it as INFERENCE when it is reasonable but not directly confirmed and state what still needs verification; use UNKNOWN when the available evidence is insufficient to determine the answer. Do not present inferences or unknowns as established conclusions.
